# CI/CD

## Protecting the main branch from direct pushes

How to stop direct pushes to `main`, so that every change has to go through a pull request.

This isn't set up yet. Strictly speaking, it's a GitHub repo setting rather than CI, but it's what makes CI useful: it's what can stop a pull request from merging until its checks pass.

### Set up the ruleset

On the repo's GitHub page:

1. Go to **Settings → Rules → Rulesets → New ruleset → New branch ruleset**.
2. Give it a name, like `protect-main`, and set **Enforcement status** to **Active**.
3. Leave **Bypass list** empty, so the rule also applies to me.
4. Under **Target branches**, choose **Add target → Include default branch**.
5. Under **Rules**, enable these:
   - **Require a pull request before merging**, with **Required approvals** set to 0
   - **Block force pushes**
   - **Restrict deletions**
6. Click **Create**.

### Things to watch for

- **Working alone:** **Required approvals** has to be 0. GitHub doesn't let me approve my own pull request, so requiring 1 would block me from merging.

### Connecting it to CI

CI would be a GitHub Actions workflow that runs checks on each pull request. The repo doesn't have one yet. Once it does, enable **Require status checks to pass** in the ruleset and select the workflow's check, so a pull request can't merge until it passes.
