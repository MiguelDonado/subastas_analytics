# Discarded and potential features

Ideas that were interesting but not needed for this project, and ideas that may be added if they're ever missed. Kept here so the reasons aren't lost if they come up again.

## Marker clusters
Grouping nearby markers into a circle with a count (`markerClusterOptions()`), which splits as you zoom in.

- **Not needed:** there are only 50–100 active auctions across Spain, and fewer once the filters are applied, so plain markers read fine.
- **Costs clicks:** a cluster isn't a marker. To select a lot from the map you'd first have to click the cluster, sometimes twice, until its marker shows. Clicking a marker would still select its row.
- **The other use, seeing where more auctions happen**, is an analysis question, not a way to find a lot to buy.

If it's ever needed: `clusterOptions = markerClusterOptions(disableClusteringAtZoom = 12)` on the blue markers, so it only groups when zoomed out, and `clearMarkerClusters()` next to `clearMarkers()`, because `clearMarkers()` doesn't remove clustered markers.

## Historical PNOA as a base map
The IGN's aerial photos from earlier years, as one more base map.

- **Rarely useful when buying:** only to check one lot you're already interested in, e.g. whether a house on rural land already existed years ago (it can matter for whether it's legal), or whether the land was farmed, burnt or flooded.
- **A base map shows one year at a time**, and what's useful is comparing years. The IGN already does that with the [PNOA comparator](https://www.ign.es/web/comparador_pnoa/), which puts two dates side by side.

If it's needed, search the lot's location in the comparator. If it becomes frequent, a link from the selected lot to the comparator would be enough.

## Land use planning layer (visorSIU)
The Ministry's [Urban Information System](https://www.mivau.gob.es/urbanismo-y-suelo/sistema-de-informacion-urbana) (SIU) shows the planning classification of land for all of Spain: urbano, urbanizable or no urbanizable.

- **Not needed:** the table already shows each lot's use and class (urbano or rústico) from the Catastro, which is enough to decide whether a lot is worth a closer look.
- **One difference to keep in mind:** the Catastro's class is for taxes, while the SIU's is the town's plan. A plot can be rústico in the Catastro and still urbanizable in the plan.

If a lot looks interesting and you need to know whether it could be built on, check it in the visorSIU: https://www.mivau.gob.es/urbanismo-y-suelo/sistema-de-informacion-urbana

## Thicker Catastro parcel lines
The parcel lines of the Catastro overlay are thin and hard to see on the aerial photo.

- **Not easy to change:** the Catastro sends ready-made images, and its service only has one style for each layer, so the line width can't be changed from leaflet.
- **The only way is CSS in the app:** an outline around the lines of the image (`filter: drop-shadow(...)`), written inside the R code. Not worth adding CSS for this.

## Hover label on the markers
A small tooltip that shows when the mouse is over a marker, without clicking, e.g. its catastral reference or its use and surface.

- **Not needed:** clicking a marker already opens its popup with all the parcel's data.

If it's ever needed, e.g. clicking parcels just to tell them apart: it's built into leaflet, one argument on `addCircleMarkers`, like `label = ~catastral_reference`.

## "Nuevos desde" filter
A date filter for the weekly check: type the day of your last visit to see only the lots loaded since then (`ingested_date >= input$new_since`). It was built and then removed.

- **Replaced by the "Estado" filter:** "Sin revisar" shows the lots you haven't decided on, without remembering the date of your last visit. And a lot you saw but didn't decide on keeps showing, while with a date it would disappear from the next check.
- **The condition:** mark every lot you look at, as Interesado or Descartado.

`gold.app_lots.ingested_date` is still there, so if it's ever needed it's only the app's part: a `dateInput` in the sidebar and one line in `filtered_lots`.

## Row colors by status
Coloring the table's rows by their status, like LinkedIn does with jobs you save or discard: e.g. light green for Interesado, grey text for Descartado.

- **Not needed:** the "Estado" column already shows each lot's status, and the app is meant to stay minimalist.

If it's ever needed: one `formatStyle` at the end of `renderDT`, with `valueColumns = "Estado"` and `columns` set to every column, plus `styleEqual("Interesado", ...)` and `styleEqual("Descartado", ...)`. `target = "row"` doesn't show anything with the app's Bootstrap 5 theme, because each cell paints its own background and text color over the row's.

## Legend for the topographic map
A legend explaining the symbols of the "Mapa Topografico" base map.

- **Not needed:** almost every symbol is clear on its own: roads, rivers, buildings, forest, contour lines. What matters for a lot is already in the table and the parcel popup, and the satellite map shows what's really there.
- **Not easy to do well:** the IGN sends the map as ready-made images, so leaflet doesn't know its symbols. The legend would have to be an image (`addControl()`), and it's long. It would also only be right at some zooms, since the IGN shows maps of different scales as you zoom, with different symbols.

If a symbol isn't clear, look it up in the IGN's legends saved in `assets/legends/`: [leyenda_topografico_IGN.jpg](../assets/legends/leyenda_topografico_IGN.jpg) and [leyenda_topografico_IGN_moderno.jpg](../assets/legends/leyenda_topografico_IGN_moderno.jpg). If it becomes frequent, a link to the legend near the map would be enough.

## Previous reviews of a re-auctioned lot
A re-auctioned lot comes in a new announcement and starts without its note and status. The app only shows the latest auction, and users can't open the database, so for them the old review is gone.

- **Columns in the table with the previous reviews: discarded.** Too many columns for something rarely needed.
- **Carrying the status over: discarded.** It may be wrong: a lot marked "too expensive" at 6000 € that comes back at 4000 € would still say so. Losing information is preferred to having wrong information, since reviewing a lot should be quick and doing it again costs little.
- **Potential: the previous note in the sidebar.** If re-reviewing becomes a nuisance, e.g. for lots you'd never want at any price, like one with a telecom antenna in the middle: a read-only line in the note card, only for the selected lot, with the note from its previous auction and the price it had then, e.g. "Nota anterior (6000 €): antena en medio". The status would still start empty.

## Built surface of flats
The surface of a lot is the area of its parcel. For a flat that's the plot of the whole building: e.g. BOE-B-2026-36159 (Valladolid) shows 505 m² for a flat of 75 m².

- **Not fixed:** most lots are rustic, and for them the parcel area is right. Urban lots are few, and the built area only fits flats: for urban land the parcel area is still the right one. So no simple rule like "urban → built area" works, and another column isn't worth it.

If it's ever needed: Goolzoom already returns the flat's own built area in `properties[0]["Constructed area"]`, next to the class and use that are already read from there.
