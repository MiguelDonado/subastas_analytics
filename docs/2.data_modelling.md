# Data modelling

Decisions about which data goes into the pipeline, and why.

**Where to place a decision:** in the layer where it takes effect, even if it mentions other layers. Each decision has its own `###` heading.

## Overview

## Bronze

### Auction PDFs are not stored

The pipeline doesn't download any PDF. There are two types related to an auction:

| PDF | Where it is |
|---|---|
| **BOE announcement** | Linked from each announcement (`url_pdf`). Its text is already stored in `announcement_text`. |
| **Pliego de condiciones** | Only on the Hacienda website. The BOE data mentions it in the text, but gives no URL. |

The Shiny app is for exploring auctions and marking the properties I'm interested in, and that only needs the data extracted from the announcement text. The PDFs are only needed at the very end, just before purchasing, and only for the few properties I've marked. At that point, opening them by hand is enough.

## Gold

### The announcement URL is only readable in the app

The URL downloaded from the BOE opens raw XML, which is hard to read. The app needs a readable page instead, and it's the same URL with `xml` changed to `txt`:

| Where | Column | Value |
|---|---|---|
| `bronze.auctions` | `source_url` | XML link, unchanged |
| `silver.auctions` | `source_url` | XML link, unchanged |
| `gold.dim_auctions` | `source_url` | XML link, unchanged |
| `gold.app_lots` (view) | `announcement_url` | Readable link, renamed here |

The tables keep `source_url` because it records where the data was actually downloaded from. The readable link is only a display need of the app, so it's calculated in the view, and it has a different name because it's no longer where the data came from.
