# Shiny

Notes on how the Shiny dashboard is built.

## Cards
`card()` (from bslib) wraps a piece of the page, like the map or the table. It's more than padding:

- **Frame:** border, rounded corners, a light shadow and inner padding, so each part looks like its own panel.
- **Header and footer:** `card(card_header("Lotes"), DTOutput("lots"))` adds a title bar on top.
- **Full screen:** `card(..., full_screen = TRUE)` adds an expand icon in the corner.
- **Fills the space:** `page_sidebar` fills the browser window and each card takes a share of the height. The content (map, table) stretches to fill its card, and scrolls inside it if it's taller. Without cards, the map and the table compete for the space and you have to set heights by hand.

To give the map more height than the table:

```r
layout_columns(
  col_widths = 12,
  row_heights = c(3, 2),
  card(leafletOutput("map")),
  card(DTOutput("lots"))
)
```

### What we use
- **Full screen on both cards.** Very useful: the map gets big enough to judge a parcel on the aerial photo, and the table can show many lots with all their columns.
- **Header only when it says something useful**, e.g. the number of lots that match the filters. A header that just says "Mapa" or "Lotes" only takes space.
- **No footer.** The map already shows its attributions and the table its paging.

## layout_columns
Places its children on a grid 12 columns wide.

- **`col_widths`:** how many columns each child takes, in order. `c(8, 4)` puts two side by side; when a row is full the next child goes below. A single `12` puts each child on its own row (our map above the table). Negative numbers leave an empty gap.
- **`row_heights`:** how the height is split between rows. `c(3, 2)` gives 60% / 40%; `c("500px", "1fr")` gives a fixed first row and the rest to the second.

## selectInput or selectizeInput
`selectizeInput()` is very similar to `selectInput()`, but it also takes an `options` argument for extra settings, such as a placeholder or a remove button:

```r
selectizeInput("province", "Provincia", choices, multiple = TRUE,
               options = list(placeholder = "Todas", plugins = list("remove_button")))
```

- **`placeholder`:** grey text shown when nothing is selected.
- **`remove_button`:** a × on each selected value to remove it.

## Recompute only when a button is clicked
By default, a reactive expression is recomputed every time one of the inputs it uses changes. To control when that happens, we add an action button and build the reactive expression with `eventReactive()` in the server function. The reactive expression is only recomputed when the button is clicked: it still reads the values of the other inputs, but it no longer depends on them, only on the button.

```r
filtered_lots <- eventReactive(input$search, {
  lots |> filter(...)   # reads input$province, input$price_max...
}, ignoreNULL = FALSE)
```

**`ignoreNULL = FALSE`:** a button that hasn't been clicked yet counts as "null", so by default the reactive expression isn't computed until the first click, and the table starts empty. With `ignoreNULL = FALSE` the reactive expression is also computed when the app starts, before any click (with the filters empty, so it shows all the lots).

## Clicking a marker selects its row
Each marker gets an id with `addCircleMarkers(layerId = ~catastral_reference)`. When a marker is clicked, Shiny receives its id (catastral reference) in `input$map_marker_click$id`. From there:

1. **Marker → lot:** look up the catastral reference in the map's points to get its `lot_id`.
2. **Lot → row:** find the row of the table with that `lot_id`.
3. **Select it:** `dataTableProxy("lots") |> selectRows(row)` selects it in the table that's already drawn, without rebuilding it.

The id is the catastral reference because leaflet needs each marker's id to be unique.

To also move the table to the page of that row, there are two positions:

1. **Position in the original table:** the row number in `filtered_lots()`, before any sorting. This is the `row` used by `selectRows`, e.g. row 12.
2. **Position on screen now:** `input$lots_rows_all` lists the original row numbers in the order they're shown right now, after sorting, e.g. `c(7, 3, 12, ...)`. Looking for 12 in that list gives where it is shown: 3rd place.

The page comes from the second one: with 5 rows per page, 3rd place is page 1.

## No search box in the table
The table has no search box (`dom = "tip"` in the DT options: only the table, the info line and the pages). The search box only hides rows of the table, so the map would still show the markers of the hidden lots. All the filtering is done in the sidebar, so the table and the map always show the same lots.

## Selecting a row highlights and zooms to its markers
A row can be selected in two ways: by clicking it in the table, or by clicking one of its markers on the map (which selects its row, see above). Only one row can be selected at a time (`selection = "single"` in `datatable`). Either way, DT stores the selected row's number in `input$lots_rows_selected`, so that input is what triggers the highlight:

```r
observeEvent(input$lots_rows_selected, { ... }, ignoreNULL = FALSE)
```

When it changes:

1. **Remove the previous highlight:** `clearGroup("selected")` removes the red markers of the lot selected before. The blue markers stay.
2. **Draw the lot's markers in red on top:** the same references, drawn again in red, in the group `"selected"`.
3. **Zoom to them:** `fitBounds` to that lot's references.

A lot can be deselected in two ways:

- **Clicking the selected row again** in the table.
- **Clicking one of its red markers** on the map. The red markers sit on top of the blue ones, so they catch the click. They have no id, so `input$map_marker_click$id` is `NULL`, and the marker-click code takes that as "deselect": `selectRows(NULL)`.

Either way `input$lots_rows_selected` becomes `NULL`. By default `observeEvent` ignores `NULL`, so the red markers would stay. With `ignoreNULL = FALSE` it still runs, removes the red markers, and draws nothing.

## Searching again clears the selection
Clicking **Buscar** recomputes `filtered_lots()`, even if the filters didn't change. Everything that uses it runs again, including `renderDT`. A `render*` function doesn't update its output, it replaces it: the browser gets a brand-new table, with no selection, on the first page and in the original order.

So `input$lots_rows_selected` becomes `NULL` and the red markers are removed. The markers `observe` also runs and redraws the blue markers for the new results. This makes sense: after a new search the rows can be different lots, so the old selection could point to the wrong one.

The map doesn't lose anything, because it's only changed through `leafletProxy`, which updates the map that's already drawn instead of replacing it.

## Extensions
A list of packages that add things to Shiny: https://github.com/nanxstats/awesome-shiny-extensions

- **shinydisconnect:** when the app loses the connection to the server (the session times out after being idle, an R error ends it, or the app is redeployed), the page just turns grey and stops responding. With this package it shows a clear message and a button to reload.
- **shinytest2 (in the future):** end-to-end tests, e.g. click a marker and check that its row is selected.
