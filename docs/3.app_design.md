# App design

Design of the final application: a Shiny for Python app to explore the auctioned properties, filter them, see them on a map and mark the ones of interest.

## Layout
- **Left sidebar:** filters.
- **Main area, top:** map with the catastral references of the results.
- **Main area, bottom:** table with the results and their main characteristics, one row per lot.

Clicking a row in the table shows all of the lot's catastral references on the map, zoomed to fit them. Clicking a point on the map highlights the row of its lot in the table.

## Map
QGIS is a desktop application and can't be embedded in a Shiny page, so the app uses a web map library: **ipyleaflet**, through `shinywidgets`.
- It has a built-in control to switch between layers.
- It can zoom the map to fit an area (`fit_bounds`) without redrawing it, which is what clicking a row needs.
- It reports marker clicks back to Shiny, so the map can also select rows in the table.

Layers, all from public map services:
- **Base map:** OpenStreetMap.
- **Aerial photo:** PNOA orthophoto from the IGN.
- **Catastro parcels:** the Catastro's public map service (WMS), which draws the parcel outlines over the map.

QGIS is still useful outside the app, to explore the data or prepare layers.

## One table row = one lot
Prices are stored per **lot**, but coordinates and surface are stored per **catastral reference**, and one lot can have several. So the table displays the view `gold.app_lots`, where each row is a lot, with:
- total surface (sum of its catastral references)
- starting price
- price per m²
- municipio and province
- use and class
- qualification (the most common among its catastral references)

The table only contains the last auction of each lot, which are the rows of the view with `is_latest = true`. A lot that is auctioned again keeps the same catastral references, so the view recognises its earlier auctions by that list of catastral references. Earlier auctions aren't shown because they aren't relevant when deciding whether to buy a property, but they can still be queried directly in the gold tables.

The map can't use this view, because it needs one point per catastral reference. It reads the coordinates from `gold.dim_catastral_references`, through `gold.lots_catastral_references_bridge`. The price and surface filters work on the lot-level values of the table.

Each row also links to the BOE announcement (`announcement_url`).

## Filters
- **Province:** multi-select box; empty means all provinces.
- **Municipio:** multi-select, narrowed to the provinces chosen.
- **Starting price:** range.
- **Surface:** range.
- **Price per m²:** range. Probably the most useful number for comparing properties.
- **Use** and **class** (urbano / rústico).
- **Auction date:** range, plus an "only auctions not held yet" switch. Past auctions are mostly useful for analysis, not for deciding.
- **Status:** filter by the user's mark (see below), e.g. hide the discarded ones.

Qualification isn't a filter. It's secondary information, not important enough to hide a property or to decide on buying it. It's only shown in the table, to confirm what kind of trees an interesting property has.

## Marking lots of interest
This is the final part to build, along with the **Status** filter that depends on it.

The user can mark each lot as **interested / maybe / discarded** and add a free-text note.

These marks are data the user enters, while bronze, silver and gold are written by the pipeline and can be rebuilt. So they live in their own schema, outside the medallion layers:

```
app.lot_reviews (boe_ref, lot_number, status, notes, updated_at)
```

The table is keyed by **`boe_ref` + `lot_number`**, not `lot_id`. `lot_id` is generated automatically, so rebuilding silver gives every lot a new number and the marks would point to the wrong lots. The BOE reference and lot number never change.

## What this means for gold
The app needs a table with one row per lot holding everything it shows and filters on. Gold can still be a star schema for analysis, and the app's table reads from a view built on it, `gold.app_lots`.

Still missing from the view:
- price per m²
- the marks from `app.lot_reviews`
