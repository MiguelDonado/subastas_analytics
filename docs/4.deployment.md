# Deployment

Where each part of the project runs, the other setups that were possible, and how Cloudflare Tunnel would have worked in them.

## Final setup

This is the same setup as `cgm-analytics`:

| Part | Where it runs |
|---|---|
| Airflow containers | My laptop |
| Database | Neon |
| Web application | Posit Connect Cloud |

```
Airflow (laptop) → Neon ← Web application (Posit Connect Cloud) ← Visitors
```

The Raspberry Pi isn't part of this setup. It also wasn't going to run the Airflow containers in any of the setups below, because they are heavy and the Pi only has 8 GB of RAM.

Neon and Posit Connect Cloud are already reachable from the internet, so nothing has to be configured to accept incoming connections.

## Stopping Airflow doesn't affect the database or the web application

The systemd service stops the containers with `astro dev stop`. That only stops the Airflow containers on my laptop. The database and the web application are still accessible, because they run in the cloud.

The problem would come from running everything locally. The most normal setup for that is to have everything in the same Compose project, so stopping Airflow would also shut down the database and the web application.

The workaround would be to put them in another Compose project, so that stopping or removing the Airflow project wouldn't affect them.

## Why a Pi needs extra work

By default, a home router blocks incoming connections from the internet. A browser can still receive webpages because those are responses to requests that started inside the network. A connection that starts outside the network has no such request, so the router drops it.

Letting a device in the network accept incoming connections normally means configuring port forwarding, dynamic DNS and TLS, and it doesn't work behind CGNAT. Cloudflare Tunnel avoids this configuration.

## How Cloudflare Tunnel works

`cloudflared` runs on the Pi and opens an outgoing connection to a Cloudflare server. The router allows it, because it starts inside the network, and the connection stays open.

Cloudflare publishes a domain. Traffic sent to that domain reaches Cloudflare, which forwards it to the Pi through the connection that is already open. It isn't a redirect: clients only talk to Cloudflare, and never connect to the Pi directly.

### Exposing a web application

```
Visitor's browser → Cloudflare → cloudflared (Pi) → Web application
```

Only the Pi needs `cloudflared`. Browsers speak HTTP, and an HTTP request says which domain it wants, so Cloudflare knows which tunnel to forward it to. Visitors don't have to install anything.

### Exposing a database

```
Airflow → cloudflared (laptop) → Cloudflare → cloudflared (Pi) → Database
```

Both sides need `cloudflared`. A database client speaks the Postgres protocol instead of HTTP, so it can't connect directly to the domain that Cloudflare publishes. `cloudflared` on the client wraps the traffic in a form that Cloudflare accepts, and the client connects to `cloudflared` as if it were a local database.

## Other possible setups

### Database and web application on the Pi

| Part | Where it runs |
|---|---|
| Airflow containers | My laptop |
| Database | Pi |
| Web application | Pi |

This was also relatively easy to set up, with `cloudflared` installed on both the laptop and the Pi:

- **On the laptop:** so that the Airflow containers can write to the database on the Pi.
- **On the Pi:** so that it can receive the traffic from Cloudflare.

Visitors would go to the domain published by Cloudflare, which would forward their traffic to the Pi.

```
Airflow (laptop) → cloudflared (laptop) → Cloudflare → cloudflared (Pi) → Database
Visitors → Cloudflare → cloudflared (Pi) → Web application → Database
```

### Only the web application on the Pi

| Part | Where it runs |
|---|---|
| Airflow containers | My laptop |
| Database | Neon |
| Web application | Pi |

`cloudflared` would only be installed on the Pi, so that visitors can reach the web application through the tunnel. The laptop wouldn't need it, because Airflow would connect directly to Neon.

```
Airflow (laptop) → Neon ← Web application (Pi) ← cloudflared (Pi) ← Cloudflare ← Visitors
```
